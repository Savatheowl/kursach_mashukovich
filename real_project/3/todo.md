Ниже представлен **промт** для другой нейросети, которая будет реализовывать проект на **PHP, HTML, CSS** с использованием **PDO** для работы с MySQL. Все упоминания AJAX, JavaScript и серверных настроек удалены, вместо этого используются классические формы и перезагрузка страницы.

# Задание: разработать веб-приложение на PHP + HTML + CSS (с PDO)

## Общие требования

- **Стек:** только PHP (без фреймворков), HTML, CSS. JavaScript **не используется**.
- **База данных:** MySQL, все запросы выполняются через **PDO**.
- **Сессии:** стандартные PHP-сессии для авторизации.
- Все действия (регистрация, вход, добавление в корзину, оформление заказа и т.д.) выполняются **с перезагрузкой страницы** через отправку форм (POST-запросы).
- Код должен быть структурирован (рекомендуется разделение на контроллеры, модели, шаблоны).

---

## 1. Структура проекта и база данных

### 1.1. Папки и файлы (пример)

```
project/
├── index.php - страница "О нас"
├── database.php (PDO подключение)
├── pages/ - все страницы, включая админ панель
├── css/
```

### 1.2. База данных

Создать таблицы:

**users**
- id (INT, PK, AUTO_INCREMENT)
- name (VARCHAR)
- surname (VARCHAR)
- patronymic (VARCHAR, NULL)
- login (VARCHAR, UNIQUE)
- email (VARCHAR)
- password (VARCHAR – хеш)
- role (ENUM: 'admin', 'client', 'visitor')

**categories**
- id (INT, PK, AI)
- name (VARCHAR)

**dishes**
- id (INT, PK, AI)
- name (VARCHAR)
- photo (VARCHAR – путь к файлу)
- price (DECIMAL)
- country (VARCHAR)
- category_id (INT, FOREIGN KEY -> categories.id)
- composition (TEXT)
- in_stock (INT)
- is_published (BOOLEAN)
- created_at (DATETIME)

**cart**
- id (INT, PK, AI)
- user_id (INT, FOREIGN KEY -> users.id)
- dish_id (INT, FOREIGN KEY -> dishes.id)
- quantity (INT)

**orders**
- id (INT, PK, AI)
- user_id (INT, FOREIGN KEY -> users.id)
- status (ENUM: 'new', 'confirmed', 'cancelled')
- cancel_reason (TEXT, NULL)
- created_at (DATETIME)

**order_items**
- id (INT, PK, AI)
- order_id (INT, FOREIGN KEY -> orders.id)
- dish_id (INT, FOREIGN KEY -> dishes.id)
- quantity (INT)

## 2. Аутентификация

### 2.1. Регистрация

- Страница `/register` с формой (метод POST):
  - Имя (name) – только буквы (кириллица/латиница), обязательное
  - Фамилия (surname) – аналогично
  - Отчество (patronymic) – необязательное
  - Логин (login) – уникальный
  - Email
  - Пароль (password) – длина ≥ 6
  - Повтор пароля (password_repeat)

- **Серверная валидация:** проверка формата, уникальности логина, совпадения паролей. При ошибках – вернуть форму с сообщениями.
- При успехе – создать пользователя с ролью `visitor` (или `client`), перенаправить на страницу входа.

### 2.2. Вход

- Страница `/login` с формой (логин, пароль).
- После отправки – проверить учётные данные, установить сессию, перенаправить на `/about`.
- При ошибке – показать сообщение на той же странице.

### 2.3. Выход

- Ссылка «Выйти» – уничтожить сессию и перенаправить на `/about`.

## 3. Навигация (общее меню)

Верхнее меню со ссылками:
- «О нас» (`/about`)
- «Меню» (`/menu`)
- «Где нас найти?» (`/contacts`)
- Если пользователь не авторизован: «Вход» (`/login`), «Регистрация» (`/register`)
- Если авторизован: «Выйти» (`/logout`), а для роли `client` – «Корзина» (`/cart`)
- Для `admin` – ссылка на админ-панель (`/admin`)

---

## 4. Страница «О нас» (`/about`)

- Логотип компании (изображение)
- Девиз компании (текст)
- Слайдер «Новинки компании» – последние 5 добавленных блюд (`ORDER BY created_at DESC LIMIT 5`). Вывести фото и название. Реализовать слайдер можно средствами CSS (например, горизонтальный скролл или CSS-анимация без JavaScript).

---

## 5. Страница «Меню» (`/menu`)

- Показывать только блюда с `in_stock > 0` и `is_published = true`.
- Сортировка по умолчанию: новые → старые (`created_at DESC`).
- Форма с элементами управления:
  - сортировка (по стране, по наименованию, по цене)
  - фильтр по категориям (выпадающий список или чекбоксы – значения из таблицы `categories`)
- При отправке формы – перезагрузка страницы с применёнными параметрами.
- Каждое блюдо – карточка: фото, название, цена. Клик по карточке ведёт на `/dish?id=...`.
- Для авторизованных пользователей с ролью `client` – кнопка «В корзину» (форма POST на `/cart/add`).

---

## 6. Страница товара (`/dish?id=N`)

- Отобразить:
  - фото
  - название
  - цена
  - страна
  - категория
  - состав
- Если пользователь авторизован и имеет роль `client` – кнопка «В корзину» (форма POST на `/cart/add` с dish_id).

---

## 7. Страница «Где нас найти?» (`/contacts`)

- Встроенная карта (iframe Яндекс.Карт или Google Maps) – пример адреса.
- Контактные данные: адрес, телефон, email.

---

## 8. Корзина (только для роли `client`)

### 8.1. Добавление в корзину

- При отправке формы «В корзину» (POST) на сервер:
  - добавить запись в таблицу `cart` (если уже есть – увеличить `quantity`).
  - перенаправить обратно на страницу, откуда пришли (или на `/cart`).

### 8.2. Страница корзины (`/cart`)

- Показать все позиции текущего пользователя.
- Для каждой позиции:
  - название, цена, количество
  - форма с кнопками «+» и «-» (каждая – отдельная форма с полем `action` и `dish_id`). При отправке – обновить количество в `cart` (с учётом остатка `in_stock` – нельзя превысить).
  - кнопка «Удалить» – удалить позицию полностью.
- Отобразить итоговую сумму.
- Кнопка «Сформировать заказ» – ведёт на страницу оформления.

### 8.3. Оформление заказа (`/checkout`)

- Форма с полем «Пароль» (подтверждение пароля пользователя).
- При отправке (POST) – проверить пароль (через `password_verify`).
- Если неверен – показать сообщение об ошибке.
- Если верен:
  - создать запись в `orders` (статус `new`)
  - перенести позиции из `cart` в `order_items`
  - очистить `cart` для этого пользователя
  - перенаправить на `/my-orders`

---

## 9. Просмотр заказов клиентом (`/my-orders`)

- Список заказов текущего пользователя, отсортированный от новых к старым.
- Для каждого заказа:
  - состав (названия блюд, количество)
  - общая сумма
  - статус (`new`, `confirmed`, `cancelled`)
- Если статус `new` – рядом с заказом кнопка «Удалить» (форма POST, удаляет заказ или меняет статус на `cancelled` с причиной «Отменён пользователем»).

---

## 10. Админ-панель (`/admin`)

- Доступ только для пользователя с ролью `admin`. При попытке зайти без прав – редирект или 403.
- **Предварительно в БД должен быть создан администратор:** логин `admin`, пароль `admin55` (пароль захэширован).

### 10.1. Управление товарами (`/admin/dishes`)

- Список всех блюд (включая неопубликованные и с нулевым остатком).
- Форма добавления нового блюда:
  - название, фото (загрузка файла), цена, страна, категория (выпадающий список), состав, количество, опубликовано (checkbox)
- Для каждого блюда – ссылки «Редактировать» и «Удалить» (с подтверждением).
- Редактирование – форма с предзаполненными данными.

### 10.2. Управление категориями (`/admin/categories`)

- Список категорий.
- Форма добавления новой категории.
- Кнопка «Удалить» для каждой категории (если есть блюда – показывать ошибку).

### 10.3. Управление заказами (`/admin/orders`)

- Фильтр по статусу: `new`, `confirmed`, `cancelled`. По умолчанию – `new`.
- Для каждого заказа показать:
  - ФИО заказчика
  - состав блюд (названия, количество)
  - общее количество блюд
- Действия:
  - «Подтвердить» – изменить статус на `confirmed`
  - «Отменить» – форма с полем «Причина отказа» (обязательное), после отправки статус → `cancelled`, причина сохраняется в `cancel_reason`

## 11. Дополнительные требования к реализации

- **Все запросы к БД выполняются через PDO** (подготовленные выражения для защиты от SQL-инъекций).
- Пароли пользователей хранить в виде хеша (`password_hash`).
- Загрузка изображений для блюд – сохранять файлы в папку `/uploads/dishes/`, в БД сохранять относительный путь.
- Внешний вид – адаптивный, аккуратный CSS (можно Flexbox/Grid). Слайдер на главной – чисто CSS (например, `overflow-x: auto` или карусель на CSS-свойствах).
- Навигация – единое меню на всех страницах (например, через `include`).

- [ ] Сайт работает локально (или на любом хостинге с PHP+MySQL) без ошибок.
- [ ] Админ-панель доступна по `/admin` (логин admin / admin55).

- [ ] Оформление заказа требует пароль и проверяет его.
- [ ] Администратор может добавлять/редактировать/удалять блюда и категории, изменять статусы заказов.
